# 目录内去重：类型分组与自主保留副本

## Goal

用户能在目录内去重结果中按类型浏览、自行指定唯一保留副本，并安全批量勾选其余副本。用户已授权通过 herdr 同工作区现有 4 个 Pi 完成，随后 push、tag、CI/CD。

## Background

- 当前基线为 93fef45，工作区干净；上一轮 v1.2.2 已发布，不改写已有 tag。
- `folder_dedupe_gui.py:2068` 由核心分组生成固定保留行，当前没有切换入口。
- `folder_dedupe_gui.py:1505` 对所有类型请求预览；`:1655` 已有全选/反选基础逻辑，应扩展而非另造。
- `scan_record_core.py:400` 起严格验证 keeper/target 状态；切换必须同步实际结果角色。

## Requirements

- R1：目录内去重结果分为照片、视频、其他三组，显示数量；保留重复组边界。
- R2：其他文件不请求缩略图或详情预览，切换到其他时清空旧图。
- R3：默认依原策略保留一份；用户可选同组另一份作为保留项。A/B/C 默认保留 A，改为 B 后仅 B 受保护，A 可勾选回收，C 的合法勾选状态保留。
- R4：提供显眼、可点击的全选、取消全选、反选，作用于当前显示分组中的合法待回收行。保留/异常/不一致/已处理行不可被批量选中。
- R5：切换后导出/导入恢复新保留关系与逐路径状态；旧 v1 记录继续可读。忙、失效、取消结果不允许切换；已处理组不可通过切换恢复为待处理。
- R6：仍使用共享大小、完整 SHA-256、逐字节验证及回收前复核，仅移至回收站；目录比对 A/B 角色不变。
- R7：完成独立/内嵌、中英、全量回归与独立复核后提交并 push，新建后继版本 tag，跟踪 CI/CD 和发布资产。保持现有 Pi 模型，不切换供应商。
- R8（用户追加）：修复首次远端 CI 暴露的异步完成回归；检查现有子分支，将已验证的全部工作合入 main，并从 main 发布新版本。

## Acceptance Criteria

- [x] 照片/视频/其他均可独立查看，数量正确，无重复组被拆散。（R1）
- [x] 选择其他文件后，无缩略图/预览加载请求且旧图片消失。（R2）
- [x] A/B/C 改为保留 B 后，B 无回收资格，A 可回收；实际 worker 使用 B 为参照。（R3/R6）
- [x] 实际按钮点击全选/反选仅影响当前组合法副本，保留行始终未勾选。（R4）
- [x] 改保留项后记录往返角色/勾选一致，旧记录兼容，坏记录和已处理状态不可获得回收资格。（R5）
- [x] 缺失/变化文件回收前复核不通过，不调用真实回收；全部自动测试使用临时目录和 mock。（R6）
- [ ] 全量测试、两种布局和语言检查通过；push/tag 的 CI 结果与资产校验有证据。（R7）
- [ ] 延迟 UI drain 的确定性回归通过；相关子分支均被 main 包含，main 新提交 CI 与新版本发布通过。（R8）

## Out of Scope

不改 A/B 目录比对保留方向；不引入永久删除、模糊查重、跨版本记录迁移或新依赖；不重构无关页面。真实 OneDrive 仅联机文件仍无端到端验证环境。
