# 目录内去重扫描覆盖统计

## Goal

显著显示扫描文件夹与文件总数、纳入与跳过原因及哈希候选数，便于核对扫描完整性

## Requirements

- R1：目录内去重在醒目的常驻位置显示当前根下已发现的子文件夹数（不含根自身）和普通文件数（包含空文件及范围过滤文件）。隐藏文件按既有规则正常统计，OneDrive 普通占位文件不因云属性漏计。
- R2：实时显示纳入查重、Hash 候选、大小唯一无需 Hash、空文件、范围过滤、链接/联接跳过和无法读取项，解释 Hash 分母不是文件总数，未算 Hash 不代表重复。扫描仅进行既有的一次目录遍历，不新增文件内容读取。
- R3：取消、目录/条目读取失败时显示已发现数量并明确“不完整”；不能将无法进入子目录中的未知文件推算为零。目录枚举尚未完成时显示进行中及 Hash 数量待确定。
- R4：完成、零候选、扫描失败、重扫、清空、语言切换均正确刷新；统计不随照片/视频/其他分类隐藏、勾选或 keeper 变化而改变。独立/内嵌、中英布局均可读不重叠。
- R5：保持现有扫描判重及回收安全语义。新统计沿已有后台 worker 信号传递、节流发布，界面主线程不访问磁盘。
- R6：本轮不改既有严格 schema v1 扫描记录；导入历史只有既有 scanned_files/hashed_files 时，明确“历史记录未保存目录总数”，不能将未知统计显示为零或现场重扫冒充历史。
- R7：软件按既有策略先默认保留一份；用户可通过明确的行级入口把同组任一尚未处理副本设为保留，旧保留转为默认勾选的待回收项。可反复切换，不能锁死软件默认项，回收前安全守卫保持。
- R8：照片、视频、其他三个分类可各自独立回收。回收按钮和确认框明确当前分类，只提交该分类勾选且合法的副本，其它分类维持原勾选和状态。全选/反选仍只作用当前分类；数量及容量须明确展示口径。
- R9：目录内去重与目录比对结果表格的鼠标滚轮不能因缩略图行高而一次跳多行；标准一格约40–60像素，触控板像素增量可细滚。复用轻量滚动配置，不改变其它页面。

## Acceptance Criteria

- 混合嵌套/空目录/同大小及唯一大小/空文件/范围外文件 fixture，发现文件数等于纳入+空文件+范围过滤（先判空再判范围），Hash 候选与 Hash 分母相符，大小唯一项不触发哈希。
- 链接不跟随且数量可见；模拟目录不可读、单条目 stat 失败、迭代中断和取消，均保留已有计数并说明覆盖不完整。
- 真实 worker 的实时统计先于最终 ScanResult 到达；进度发布有界且 UI 无重复遍历。
- 真正按钮扫描、无重复结果、重扫、旧记录导入和语言切换后统计语义正确；全量回归及语法检查通过。
- 真实鼠标选择同组另一个副本保留，旧保留成为回收目标，真实回收worker使用新保留；记录导入导出保留角色。切回原保留正常。
- 三类均有勾选时，点击当前分类回收只提交该类；回收后能再选择另一类独立执行，隐藏分类不被误回收。
- 真实QWheelEvent验证标准滚轮及触控板像素事件，独立/内嵌、中英布局保持可用。
