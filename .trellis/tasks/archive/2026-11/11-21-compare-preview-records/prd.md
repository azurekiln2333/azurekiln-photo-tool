# 目录比对预览、选择与扫描记录修复

## 目标与授权

修复目录比对与目录内去重两页的预览布局和视频缩略图，增加批量勾选与可恢复的扫描记录。用户已在看到修复范围后明确要求“快点先修……修完 push tag cicd”；该回复同时授权本任务创建、实施、提交、推送及新补丁版本发布，无需重复确认。

## 已确认问题

- `media_thumbnail.py:684` 固定图像宽度，`:690` 普通 wordWrap 无法约束长路径；两槽 minimumSizeHint 被长连续路径撑开，等分及 splitter 失效。
- `media_thumbnail.py:453` 仅 Shell → 图片解码，缺视频解码回退；`:510` 失败缓存与缓存的 mtime 让暂时失败永久停留到 clear。
- 两页只有逐行勾选，没有批量勾选，也没有扫描记录持久化；现有 JSON 仅保存页面偏好。
- 本机 H.264/HEVC 样例可用 Shell/FFmpeg 取图；真实 OneDrive 首次失败尚未定位，不能声称云端端到端验证通过。

## 需求

- R1：A/B 两预览槽始终等宽，长路径可任意字符换行；图像按可用宽度等比缩放。表格/预览分隔条能在合理范围拖动，独立与内嵌均可用。
- R2：两页新增全选、全不选、反选，仅作用于合法待回收副本；保留文件、异常、碰撞、已处理、取消或失效结果不可被批量选中。
- R3：两页可导出/导入带版本的 JSON 扫描记录，包括模式、扫描根、选项、完整指纹/文件快照、分组、异常、统计及勾选/处理状态；恢复后可继续核对。记录不嵌入媒体文件。
- R4：导入记录是不可信历史。拒绝越界路径、错误角色、重复目标或保留项与目标相交；从历史执行回收强制逐字节重验当前文件。取消/失效记录不能回收；坏记录不破坏当前显示。
- R5：视频有不依赖 Windows Shell 缓存的视频解码回退，有超时；失败可有限重试并反馈原因，已下载文件可恢复预览。发布包应包含可用的视频回退能力。
- R6：所有新增界面文案中英完整，操作不阻塞主线程；复用两页共用核心，媒体统计及旧页面兼容。
- R7：完成回归与独立复核、提交 push、打补丁版本标签并检查 CI/CD 与发布资产。首次 v1.2.1 标签已推送，但 CI 暴露关闭回归测试对外部 ExifTool 的隐式依赖；保留该标签不覆盖，修正测试隔离和 CI 超时后以 v1.2.2 完成发布。

## 验收

- AC1：连续长路径不改变 A/B 等宽；拖动改变左右宽度且无内容撑开（R1）。
- AC2：真实按钮点击覆盖三种批量勾选，异常/保留/失效行受保护（R2）。
- AC3：两种模式记录往返保留分组/指纹/状态；错误模式/版本/越界/角色冲突被拒绝；导入后修改或删除文件不会误回收（R3–R4）。
- AC4：强制 Shell 失败时，本地 H.264/HEVC 样例能解码；超时失败、暂时失败后重试均有覆盖（R5）。
- AC5：隔离 APPDATA 的独立/内嵌中英冒烟、现有核心回归、语法、diff 检查通过；没有写真实相册或回收真实用户文件（R6）。
- AC6：最终 v1.2.2 与 APP_VERSION 一致，远程 CI 成功并有 portable zip、sha256、安装包；v1.2.1 标签保留，记录首次 CI 取消原因，修复可控错误（R7）。
