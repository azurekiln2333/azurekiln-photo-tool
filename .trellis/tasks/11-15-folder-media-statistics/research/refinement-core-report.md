# README 自动创建核心修订验证（2026-11-16）

## 实现范围

- 仅修改 `media_readme_core.py`；基线提交为 `40b603c`，本次修订未提交或推送。
- `ReadmeDocument` 末尾增加兼容默认值 `exists=True`。
- 完整枚举目录确认缺失后，`load_readme` 返回 `missing` 和 UTF-8 / 无 BOM / LF 的空白文档，
  `exists=False`、`baseline=b''`、`mtime_ns=0`。同名目录、链接、联接及枚举失败返回 `error`。
- 新空白保存空文本不创建文件。实际内容先写同目录唯一临时文件并 flush/fsync，再次确认无同名项后发布：
  Windows 使用不覆盖目标的 `os.rename`；其他平台使用不覆盖目标的 `os.link`，随后清理临时路径。
- 外部抢先创建（包括不同大小写文件名、目录或链接）返回 `conflict`；成功创建返回 `exists=True` 新基线。
- 已有文件保留编码、BOM、主要换行、2 MiB 上限、字节基线检查及原子替换；删除后不改走创建。
  保存前以 `lstat` 拒绝已变成链接或非普通文件的原路径。
- LF 保存也先统一输入中的 CRLF / CR，确保新文件确实使用 LF。

2. 中文新内容创建为 UTF-8 无 BOM / LF，重新加载成功。
3. 已有空文件仍是已有文档，清空内容可保存。
4. 外部先创建 `README.TXT`，返回冲突且原字节不变。
5. 临时写入期间创建混合大小写说明文件，发布前再次检查并拒绝覆盖。
6. Windows `rename` 发布瞬间出现文件，返回冲突且外部内容不变。
7. Windows `rename` 发布瞬间出现目录，返回冲突且目录保留。
8. 已有同名目录不变为可编辑缺失文档。
9. 实际符号链接加载报错，新文档保存拒绝覆盖链接及目标。
10. 联接类型模拟返回明确错误。
11. 权限拒绝及迭代中枚举失败均不能变成缺失文档。
12. 原文件被删除后仍冲突，不重建。
13. 仅时间戳改变允许保存；外部字节改变拒绝覆盖。
14. 原路径被替换为符号链接后拒绝写入。
15. UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM、GB18030 及 LF/CRLF/CR 保持。
16. 2 MiB 精确边界可读写，超限及严格编码失败不落盘。
17. 模拟 fsync 失败：原文件不变、新文件不创建，临时文件清理。
18. 模拟发布/替换失败：原文件不变，临时文件清理。
19. 非 Windows 硬链接分支在当前 NTFS 临时目录模拟运行：成功创建、抢先创建冲突、不覆盖。
