## 可执行交互

1. 保留“媒体统计”标题，副标题仅一行 **统计文件夹内图片、视频数量**，英文等义。
2. 移除底部“扫描完成…”整张卡片及占位；必要扫描中/失败/不完整提示合并到现有汇总区，
   正常完成不增加额外行。标题、根目录卡片与表格工具栏可适当压缩间距。
3. 说明区默认编辑高度约 72–90 px（3–4 行），整个说明卡片约 120–140 px；
   窗口增高时空间给目录表。保留可拖动 splitter；以 1000×800 和 1440×900 实测表格显著增高。
4. 移除常驻“保存”“重新加载”两按钮及其行；去掉“此目录没有 readme.txt”状态和占位文案。
   保留说明标题与路径。正常状态不占额外一行，失败才显示简短错误。
5. 选中可访问目录后，无 readme 时显示可编辑的空白；输入停止约 800 ms 或焦点离开时自动保存。
   新文件使用 UTF-8 无 BOM、LF，保存在当前目录 `readme.txt`。仅查看空白不创建文件。
6. 有已有文档时保持编码/BOM/主要换行、2 MiB、外部变更保护；清空已有内容可保存为空文件。
7. 切目录/换根/重扫/关闭时先异步写完最新草稿再继续；失败停留并保留文本，必要时仍可用
   异常草稿决策（重试/放弃/取消），不能静默丢失。普通成功不弹重复 InfoBar。
8. 编辑器保存期间仍可输入；已提交的文本快照成功后更新基线，不能覆盖较新的编辑文本。
   同一时刻仅一个说明 I/O，后续草稿等旧线程 cleanup 再保存，旧路径结果不可串入新目录。

## 核心契约修订

- `ReadmeDocument` 末尾增加 `exists: bool = True`，已有文档兼容原构造。
- `load_readme` 在目录成功枚举且无文件时返回 `missing` + 空白文档（exists=False，
  path=directory/readme.txt，baseline=b''，mtime_ns=0，encoding=utf-8，bom=b''，newline=LF）。
- 只有真正 missing 可以创建。读取/枚举失败、同名目录/链接不得获得可写空白文档。
- `save_readme` 新文件先完整写同目录临时文件，再不覆盖地发布；Windows 的
  `os.rename` 遇目标已存在须返回 conflict；非 Windows 可用等价的不可覆盖发布。
  保存前若已出现任何大小写匹配的 readme 名称（包括链接/目录）则拒绝覆盖。
- 既有文档仍用字节基线检查及原子替换；删除后保持 conflict，不当作创建。
- 未编辑的新空白无需落盘；创建成功返回 exists=True 的新基线。

## 验证

- 临时目录：missing 空白可编辑、不编辑不建文件、暂停输入自动创建/修改、去焦点保存、
  UTF-8/GB18030/BOM/换行保留、外部抢先创建或修改/删除不被覆盖。
- 强制延迟保存：保存期间继续输入、不提前清除 dirty、不丢新文本；快速换目录/关闭前
  最新草稿最终落在原目录，单活跃线程，Qt 槽异常为 0，进程退出 0。
- zh/en、独立/内嵌、默认/较小尺寸截图：无脚部卡片/多余副标题/两个按钮/缺失提示，
  说明区默认紧凑，表格可见行数明显增加。
- 不写用户真实 OneDrive；最终重新打包到新的输出目录或在旧程序正常关闭后替换，
  不强制结束用户可能带草稿的运行窗口。
